# Wanderthirst

Single Next.js App Router app (no monorepo). All app code is under `src/`; there are no API routes, data layer, auth, or tests yet — it is a landing page scaffold.

## Commands

- `npm run dev` — Next.js 16 dev server (Turbopack). Use `npm`; `package-lock.json` is the only lockfile.
- `npm run lint` — runs bare `eslint` over the repo. `next lint` was removed in Next 16.
- `npx next typegen && npx tsc --noEmit` — typecheck. `next build` also typechecks.
- `npm run build` → `npm start`.
- Focused lint: `npx eslint src/app/page.tsx`.
- No test runner is configured. Don't invent `npm test` or add a framework without being asked.
- No CI workflows exist; verification is local.

## Verification order

1. `npm run lint`
2. `npx next typegen && npx tsc --noEmit`
3. `npm run build` — the only way to catch Cache Components/prerender errors before deploy.

Known baseline: `npm run lint` currently fails on `src/components/ui/carousel.tsx` (`react-hooks/set-state-in-effect`). That is vendored shadcn code, not your change; don't "fix" it unless the task touches the carousel.

## Next.js 16 configuration (differs from older training data)

- Version-matched docs live in `node_modules/next/dist/docs/` (`01-app/01-getting-started/`, `02-guides/`). Read them before using framework APIs.
- `next.config.ts` enables `cacheComponents` and `partialPrefetching`. Routes prerender by default; uncached data or request-time values (`fetch`, `cookies()`, `headers()`, `params`, `searchParams`, `Math.random()`, `Date.now()`, `new Date()`) outside `<Suspense>` break the build. Fix with a `<Suspense>` boundary, `"use cache"` + `cacheLife`, or `await io()`. See `01-app/01-getting-started/08-caching.md`.
- Route types are generated by `next dev`, `next build`, or `next typegen`. Use the global `PageProps<"/route">` / `LayoutProps<"/">` helpers; don't hand-write `params`/`searchParams` prop types. `layout.tsx` already follows this.
- `middleware.ts` is deprecated; the Next 16 file convention is `proxy.ts`.
- Keep the `turbopack.rules` CSS loader entry in `next.config.ts` — Tailwind is wired through `@tailwindcss/turbopack`.

## UI conventions

- shadcn `base-nova` style built on **Base UI** (`@base-ui/react`), not Radix. Never import `@radix-ui/*` or paste Radix-based shadcn snippets. Base UI composes with the `render` prop (`<Dialog.Close render={<Button />}>`), not Radix's `asChild`.
- Add components with `npx shadcn@latest add <name>`; aliases (`@/components`, `@/components/ui`, `@/lib`, `@/hooks`) come from `components.json`. Treat `src/components/ui/` as generated — don't restyle it when building page sections.
- `cn` is provided by the `cn` package and re-exported from `src/lib/utils.ts`. Import from `"cn"` or `@/lib/utils`; don't add `clsx`/`tailwind-merge`.
- Tailwind v4 is CSS-first: there is no `tailwind.config.*`. Theme tokens and radii are defined in `src/app/globals.css` under `@theme inline` / `:root` / `.dark`; use those CSS variables.
- Images live in `src/assets/` (static imports) and `public/`. Prefer `next/image`.

## Local gotcha
